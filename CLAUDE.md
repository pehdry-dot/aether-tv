# Aether TV — project memory

## Objective
Aether TV is a native Android TV / Google TV / Fire TV launcher (Kotlin + Jetpack Compose) with a dark cinematic
glass design. Primary target: Toshiba 43M450SU Fire TV (2026). **Verified on hardware (2026-11-21):** Fire OS 14,
Android 14 / API 34, build SL14SHIP1015, Hisense-built AFTCU9343B, MediaTek MT9676, 32-bit only (armeabi-v7a),
1.7 GB RAM, UI 1920×1080 @ 320 dpi. Fire OS sends Home to Amazon's launcher; Aether reaches Home either through
"Aether only" mode (Amazon's launcher disabled with adb, Aether set as preferred home) or `HomeButtonService`.

## Golden rules
1. **Never fake state.** Device status, media progress, notifications and network state come from real APIs or are
   shown as unknown/"Input shortcut". Shortcuts are never labelled "Connected".
2. **Everything works with a D-pad.** No touch-only interactions. Long-press and the Menu (☰) key open options.
3. **No root, no privileged APIs, no ads, no analytics.** Undocumented platform hooks (Amazon input service) must
   have fallbacks and be logged in `EventLog`.
4. **Performance first on cheap TVs.** No per-frame blur; glass samples a pre-blurred backdrop. No polling.
5. **Every setting must change real behaviour.** Don't add controls that do nothing.

## Build & test
```bash
export ANDROID_HOME=/path/to/android-sdk
./gradlew :app:assembleDebug            # app/build/outputs/apk/debug/app-debug.apk (id com.aether.tv.debug)
./gradlew :app:assembleRelease          # minified, signed with debug key unless a keystore is configured
./gradlew :app:testDebugUnitTest        # unit + Robolectric UI tests
./gradlew :app:recordRoborazziDebug --tests 'com.aether.tv.ui.ScreenshotTest'   # docs/screenshots/*.png
```
JDK 17+ (built with 21). AGP 8.13.0, Kotlin 2.2.20, Compose BOM 2025.10.00, compileSdk 36, targetSdk 34, minSdk 25.
`settings.gradle.kts` lists Google's Maven Central mirror first (some sandboxes block Maven Central's CDN);
Robolectric is pointed at the same mirror in `app/build.gradle.kts`.

## Layout
- `core/designsystem` — tokens (`Theme.kt`), glass/focus (`Glass.kt`), wallpaper + backdrop blur (`Wallpaper.kt`),
  icons (`AetherIcons.kt`, generated by `tools/gen_icons.py`), components.
- `core/model` — `LauncherSettings` (JSON in DataStore, per profile) and domain models.
- `data/*` — Room DB, repositories (apps, favorites, devices, profiles, settings, backup), media adapters.
- `platform/*` — the only code that talks to Android/Fire OS system services.
- `ui/*` — `LauncherViewModel` (single source of UI state), `MainScreen` scaffold, pages, overlays.
- Tests: `app/src/test` (JVM + Robolectric; `TestEnv` wires real repos to in-memory storage).

## Conventions
- New interactive elements: use `GlassTile` / `OptionRow` (they handle focus, OK, long-press, Menu key, focus memory).
- New rows: `BleedRow` so focus zoom isn't clipped. Lists of settings: `ToggleRow` / `ChoiceRow` / `SliderRow`.
- Overlays: add a case to `Overlay` and render it in `OverlayHost`; Back closes it; focus is restored automatically.
- Settings fields need a default value (backwards-compatible JSON).

## Home button on Fire TV (hardware facts, measured)
- `cmd package set-home-activity` is accepted but ignored while Amazon's launcher is enabled.
- With `com.amazon.tv.launcher` disabled (`pm disable-user --user 0`) and Aether preferred, Home opens Aether
  directly (~0.85 s from an app) and the TV boots straight to the preferred home. Lost with it: Amazon's main Settings
  grid (it lives inside the launcher). `settings.v2` Network/Applications/Controllers & Bluetooth/Device activities stay
  openable; Preferences, Display & Sounds and Accessibility require Amazon's private `LAUNCHER_SETTINGS` permission.
- Opening Fire TV Settings and pressing Home produce the *same* accessibility event (`HomeActivity_vNext`, text "Home"),
  and Home pressed while Amazon's launcher is showing produces none. `HomeRedirectPolicy` encodes this; keep its tests.
- HDMI switching through `KaminoInputSwitchService` with `inputType` works without a PIN; `ACTION_VIEW` passthrough
  URIs go through Live TV and hit the parental-controls PIN.

## Rendering on the M450 (measured with `dumpsys gfxinfo framestats`)
- Fire OS sets `debug.hwui.render_dirty_regions=false`: the Mali-G52 redraws the whole 1080p screen every frame, so
  every translucent layer and every draw call costs time on every frame.
- Glass (`Modifier.glass`) draws in **one AGSL pass** on Android 13+ (`GlassOnePass` in `Glass.kt`): backdrop, tint,
  sheen, border and rounded edge in a single shader. The four-draw path below it is the fallback for older Android and
  must stay visually identical; change both together. Screenshots of the two paths matched within 2/255 per channel.
- Glass inside a `GlassPanel` doesn't sample the backdrop again (`LocalGlassDepth`); big panels skip the sheen.
- Pages are kept alive once built (`MainScreen`), hidden pages are not placed, and tabs switch after ~0.2 s of rest.

## Pictures shown much smaller than stored
- Use `SharpPhoto`/`PhotoScale` (area averaging to the exact pixel size, then 1:1): bilinear shrinking >2x on the GPU
  aliases badly on this TV. Device photos and app logos already do; `LogoMask` shares `PhotoScale.resample`.

## Continue Watching and weather
- `TvWatchNextProvider` (media provider) reads Android TV's Watch Next list plus apps' "Continue …" preview channels
  (Nuvio publishes to Watch Next). Explicit column projections only. Needs `READ_TV_LISTINGS`. Resume links go through
  `WatchNextText.resumeIntent`, which only ever opens the publishing app. Keep its tests.
- Weather (`data/weather`): Open-Meteo, no key. The city is the one typed in Settings, else the time zone's city.
  It refreshes on resume and every 30 min while resumed (`LauncherViewModel.onResume`/`onPause`), never in the
  background. No reading means no weather shown; never fake it.

## App logos (Appearance ▸ App logos, default White)
- `AppLogo` shows a white logo cut out of the app's own TV banner or icon by `LogoMask` (pure, unit-tested). Sources are
  read at xxxhdpi, edges keep their anti-aliasing, and each logo is area-averaged once to the exact pixel size of its
  slot. Don't scale logos afterwards: dock items don't zoom on focus for that reason. No logo found → the colour icon.
- Home's apps row is a dock (`AppsDock` in `HomePage`, `DockItem` in `Tiles`): one `GlassPanel`, items spread evenly
  while they fit, ◀ ▶ kept inside it. "Original colours" restores the tile row.
